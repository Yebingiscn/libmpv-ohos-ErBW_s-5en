# OHAudio 工作组默认接入验收

普通 `ohaudio` PCM 和 AudioSuite 均自动探测并使用工作组，无用户设置。标记的是应用写入回调中的实际处理区间，不是 mpv 主线程，也不宣称管理 AudioSuite 内部不可见的线程。原生 Vivid、E-AC3、USB 独占及 AVPlayer 不在本次范围。

## 时序与失败回退

1. AO 初始化时 dlopen/dlsym 完整七接口，创建单个工作组。资源管理器是系统单例，不释放单例。
2. 注册实际回调线程而不是初始化线程；缓存 token，kernel TID 改变时移除旧成员并重新注册。首次/迁移注册仍在回调中发生，须重点测其开销；没有宣称整个回调绝无系统调用或 IPC。
3. 按请求输出帧数/实际输出采样率估计处理预算，不含已经排队的播放时间。使用 CLOCK_REALTIME 的绝对毫秒，不复用 mp_time_ns 或 end_time。留 10%（至少 1ms）交付余量，最长预算按 100ms 周期限制，低于 2ms 的请求不标记。高级回调可能突发连续触发，该估算不等同于系统提供的真实截止时间。
4. Start/Stop 配对，只标记非阻塞取数或 AudioSuite RenderFrame 调用区间。一个非等待门控防止工作组状态重入，不改变原音频取数行为，也不宣称修复了底层本身不支持并发回调的问题。
5. 缺接口/创建失败不改变输出；注册、移除、Start/Stop 失败使该 AO 停用调度提示，不逐帧重试。Start 失败尝试 Stop 清理可能的部分成功；Stop 未确认时销毁再次尝试。
6. 先成功 Release renderer，再释放工作组及库引用。如果释放失败或回调仍在工作，保留可选句柄；可能产生资源保留，不能把失败当作已清理成功。这不是对既有 renderer Release 异常下所有 AO/Suite 生命周期问题的全面修复。
7. ready 只代表能力/组准备好；首次成功 Start 后由现有时钟线程打印 active (PCM/AudioSuite)。回调不打印日志，销毁时 verbose 汇总 cycles/registrations，不加常态逐帧统计。

## 自动检查

- `scripts/verify-ohaudio-workgroup.sh`：缺库、逐个缺七符号、管理器/创建失败、零 token、部分创建失败、无效/溢出时间、不同采样率、预算余量、长请求上限、线程迁移、重入跳过、双线程碰撞、Start/Stop 失败、不确认静默、销毁失败保留及重复销毁。
- Python 源码连线检查：PCM/Suite 同一个平衡区间、无回调加载/创建/日志、系统时间与 mpv 时间分离、先释放 renderer 再清理组。
- 从实际源码抽取回调做宿主模拟：正常/缺库/Start 失败时 PCM 和 Suite 的输出字节、返回长度、未写尾部、原 mpv 播放时间不变，Reset 不重复注册，0 数据仍配对结束，实际回调线程变化重新注册。这不是完整 mpv/Suite 运行或真机 PCM 画质/音质测试。
- 最终 `verify.sh`：拒绝新增工作组接口的强制未解析导入，要求实现日志标记。对象文件检查不能代替最终 libmpv.so/HAP 检查。

## 真机必须复测

马良优化版和本工作组版必须分开做开/关对照，防止把 GPU 改动的收益当作工作组收益。固定片源、输出设备、音效、温度与网络状态，每组至少三次；预热 30 秒，观测 60 秒。

- 普通 PCM 与 AudioSuite 分别测：GetUnderflowCount 增量、首次/迁移注册耗时、整个回调 CPU 耗时 P95/P99、可闻断音、CPU 与功耗。耗时只在测试构建/官方工具收集，不新增产品常态逐帧日志。
- 无 GPU 压力和同时运行超分/弹幕/后台负载分别测，不保证每个设备普通 PCM 都有收益；若无收益或功耗/回调开销明显恶化，须调整默认策略。
- 44.1/48/96kHz、短/长缓冲、倍速、音乐省电路由、蓝牙/有线、前后台、暂停恢复、seek/Reset、切设备、AO 重建、反复退出。确认没有额外音频队列、延迟或 A/V 漂移。
- phone/tablet/2in1/TV：官方列出 API 20+ 支持，但必须分别验证真实系统符号与行为。x86_64 模拟器不能验证 ARM64 电视。
- 注入缺符号和各接口失败，验证原 PCM/Suite 输出不中断、失败不逐帧重试、停止后不卸载仍可能被调用的库。
